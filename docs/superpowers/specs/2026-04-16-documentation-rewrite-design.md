# Design Spec — Full Documentation Rewrite

**Date:** 2026-04-16
**Status:** Approved
**Scope:** 13 files — complete rewrite from codebase ground truth

---

## Background

A series of security fixes, architecture refactors, and feature additions landed in
the `ralph/hhh-platform-unified` branch during April 2026. None of this work was
reflected in the documentation. Additionally, `DOCUMENTATION.md` still describes the
pre-Flutter, pre-Keycloak vanilla JS / EJS architecture from October 2025 — it is
almost entirely wrong about the frontend and auth stack. This spec covers a full
rewrite of all 13 affected documents.

---

## What Changed in the Codebase (Documentation Trigger)

### Security fixes
- Participant passwords now stored as bcrypt hashes (previously plaintext)
- Timing-safe secret comparison + security headers middleware added to backend
- Shared-secret authentication added between Node.js backend and Python API service
  — new env var `API_SERVICE_SECRET`, new file `API-service/auth.py`
- IDOR closed on recommendations feedback endpoint
- Field length limits on all API request models; LLM call timeout; KB path traversal guard
- PII redacted from survey logs; `secure`/`sameSite` cookie flags; `_id` stripped from responses
- WebView navigation locked to app origin (donate + profile screens)

### Architecture refactors
- `adminRouter.js` split into domain sub-routers:
  `app/routes/admin/participantsRouter.js`, `studiesRouter.js`, `surveysRouter.js`, `notificationsRouter.js`
- Python API singletons consolidated into shared `API-service/deps.py` (lifespan-managed)
- Redis distributed lock added to notification cron (prevents duplicate dispatch)

### Features
- Token card PDF generated at participant creation time (not lazily on download)
- Legal document screen added to Flutter app; age-consent middleware and disclaimer routes removed

### Tests
- Full Jest + React Testing Library suite added for Next.js admin app (`admin/src/__tests__/`)
- IDOR regression tests; interaction tests for questionnaires, studies, knowledge-base

## Content Strategy

### How each file is rewritten

Every file is rewritten from scratch using the current codebase as ground truth,
not by patching the existing text. Sources of truth per group:

**Group 1:** `docker-compose.yml`, `docker-compose.local.yml`, `docker-compose.prod.yml`,
`stack.env`, `Makefile`, `app/routes/`, `app/app.js`, `API-service/`, `admin/`, `mobile/`.

**Group 2:** `app/routes/admin/` sub-routers, `app/services/adminParticipantService.js`,
`app/services/tokenCardService.js`, `admin/src/` (Next.js admin app).

**Group 3:** `mobile/lib/screens/`, `mobile/lib/l10n/`, `keycloak/hhh-realm.json`.

**Group 4:** `git log` since `[1.2.0]` tag.

### German translation approach

`MANUAL-de.md` and `admin-guide-de.md` are generated by translating the new English
source. Each translated file opens with:

```
<!-- MACHINE TRANSLATED from English source — human review required before publishing -->
```

This flags the files for the study team without blocking the documentation PR.

### "In progress" sections in MANUAL-en.md

Three sections are currently placeholder text. They will be filled from what actually
exists in the app:

- **Data protection:** Keycloak-based pseudonymous authentication; no PII in habit
  donations; server-side language preference only; data stored at TU Dresden.
- **Help and support:** Contact email (`study@tu-dresden.de`); Keycloak password
  reset flow; link to participant guide.
- **Legal information:** Points to the legal document screen added in commit `4d2e656`;
  summarises what the screen contains.
